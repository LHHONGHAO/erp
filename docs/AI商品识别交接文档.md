# AI 商品识别交接文档

## 目标与设计原则

AI 商品添加的图片识别结果是待复核草稿，不应把模糊匹配当成确定结果直接覆盖用户数据。当前改动围绕这条原则整理识别、复核与学习流程：

1. 类别配置值、精确样本和已学习别名属于确定匹配，可以按既有流程归一。
2. 文本相似度命中只提供候选；识别原文继续保留在可编辑字段中。
3. 用户选择候选或输入正确值后，保存商品时用“识别原文 → 最终采用值”作为学习样本。
4. 尺寸数值相同但显式单位不同，不应仅因数值部分相同而视为等价。
5. 标签或字段归属有歧义、目标字段已有内容时，保留给人工处理，避免静默覆盖。

类别常值建议仍由用户点击采用；它是补全提示，不自动填入。

## 识别与学习链路

```text
AI 商品添加页
  → MaterialModal.openSpecRecognize
  → POST /spec/sample/recognizeProduct
  → SpecRecognizeService.recognize
  → 规格值经 SpecValueSampleService.align / SpecValueNormalizer 归一
  → 识别结果弹层展示原文与候选
  → 用户选择候选或编辑最终值
  → 保存商品
  → learnRecognizedSpecValues / learnRecognizedBaseProps
  → POST /spec/sample/learnBatch
```

规格复核时，候选选择和直接编辑都会更新当前保存目标。原始 OCR 字段另行保留，提交学习时不会用修正后的值覆盖原文。归一化后原文和最终值相同时，后端跳过重复学习。

## 本次代码改动

### AI 识别复核 UI

文件：[MaterialModal.vue](../jshERP-web/src/views/material/modules/MaterialModal.vue)

- 对需要确认的普通规格显示字段识别原文和后端返回的候选写法；可点候选，也可直接编辑。
- 子规格行显示各自识别原文和候选，并分别跟踪用户确认状态。
- 用户确认或修改后，显示保存后会学习该对应关系的提示。
- 基础属性的最终值与识别原文不同时，显示原文和学习提示。
- 模糊标签匹配会对候选打分；最高分和次高分差小于 `0.05` 时不自动归属。
- 多个 OCR 标签命中同一基础字段，或目标字段已有值时，不把后续标签自动映射到该字段，避免识别卡片编辑时覆盖已有值。

### 样本匹配与文本候选

文件：[SpecValueSampleService.java](../jshERP-boot/src/main/java/com/jsh/erp/service/SpecValueSampleService.java)

- `align()` 遇到文本相似度命中时，返回原文、候选与 `similar` 状态，不再把相似样本伪装成确定命中。
- `judge()` 对高相似度文本也返回 `SUGGEST`，输入值仍是 OCR 原文，候选供用户确认。
- 模糊建议在用户确认前不增加样本 `hit_count`，避免未采纳候选反过来提高自身排序。
- 数值样本匹配增加单位兼容校验。

### 识别结果传递与学习原文

文件：[SpecRecognizeService.java](../jshERP-boot/src/main/java/com/jsh/erp/service/SpecRecognizeService.java)

- 规格维度对齐时传递候选到识别结果；文本相似命中继续保留识别值，并标记需要确认。
- 子规格识别结果分别携带原文和候选，供复核 UI 展示。
- 基础属性归一化不再自动采用低置信度的文本相似样本。
- 非子规格学习记录使用字段级 `rawValue`；之前会回退使用整张图片的 OCR 全文，可能把整段文字错误地关联到一个规格值。
- 尺寸相等性检查沿用单位兼容规则。

### 尺寸归一规则

文件：[SpecValueNormalizer.java](../jshERP-boot/src/main/java/com/jsh/erp/utils/SpecValueNormalizer.java)

- 新增 `numericKeyCompatible(left, right)`：数值维度相同，且单位至少一侧缺失或两侧相同，才允许数值键兜底。
- 完整归一化键仍优先匹配；单位缺失可以沿用已有数值兜底行为；两个显式且不同的单位不再匹配。
- 当前不做单位换算，例如不会把 `1m` 自动换算成 `100cm`。

## 数据状态说明

- 识别值：OCR 从字段或子规格提取的原文，保留用于展示及学习。
- 候选值：历史样本或类别配置提供的可能写法，不等同于确认结果。
- 最终值：用户点选或编辑后实际写入商品/SKU 的值。
- 学习样本：仅在商品保存成功后提交，内容是识别原文与最终值的对应关系。
- 类别常值及常用值：仍是用户主动选择的补全建议。

## 验证情况与注意事项

- 本次只做了代码静态检查；未运行前端构建、后端构建或自动化测试。
- 变更仅在本地工作区，尚未部署到 `www.innas.xyz`。
- 建议后续补充用例：文本模糊候选保留原文、选候选/手工改值后的学习样本、显式不同单位不匹配、缺失单位兜底、标签同分不自动归属、重复标签及已有字段不被覆盖。
- 需要特别检查尺寸配置中的单位是否有需要正式换算的业务场景；当前实现按“不同显式单位不等价”保护数据。
