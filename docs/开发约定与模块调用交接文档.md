### 当前架构与持久化数据约定（2026-11-09）

- 后端：`jshERP-boot`（Spring Boot 2.0 / Java 8）；Web：`jshERP-web`（Vue）；移动端入口：`jshERP-mobile`。客户端统一调用后端 API，业务数据由后端访问 MySQL；客户端不直接连接数据库。
- MySQL 与 Redis 是独立服务。连接由 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD` 等运行环境变量提供；仓库默认配置不再包含数据库口令。生产应用使用 `jsherp` 专用账号。
- 本次调整的是数据库连接凭据和部署数据布局，没有修改业务表结构或新增数据库迁移脚本。已有 MySQL 数据卷需按部署说明创建应用账号后再切换连接凭据。
- 持久化应用文件与程序发布目录分开。Windows 本地路径由 `deploy.config.json` 管理，当前为 `D:/jshERP/data` 和 `D:/jshERP/backup`；Linux Compose 默认使用 `/srv/jsherp-data` 与 `/srv/jsherp-backup`，可在部署目录 `.env` 覆盖。
- 应用数据目录用于上传文件、OCR/证书配置、导出缓存和日志。MySQL 数据文件由 MySQL 数据目录管理；数据库导出备份放在独立备份目录。`deploy-local.ps1` 仅创建备份目录，不会自动执行数据库备份。
- Compose 不对宿主机映射 MySQL 端口；外部客户端通过 HTTPS/API 访问 ERP。远程部署使用 SSH 密钥认证和经核实的 HostKey，不在脚本里存 SSH 密码。
- 部署模板在 `deploy/`；远程 `.env`、证书和运行数据不提交。`deploy.ps1` 仅上传 `.env.example`，要求远程先准备好 `.env`。已有 MySQL 数据卷不会因更新环境变量自动创建 `jsherp` 账号，升级操作见 [部署数据与备份](部署数据与备份.md)。
- 本机旧数据迁移：新版 `deploy-local.ps1` 在新数据目录为空且仓库根 `data/` 有内容时会复制数据，并保留原目录；已有新目录不会被覆盖。

## 2. 模块调用手册

### 2.1 scrollBlank —— 手机端整页滚动空白检测

**文件**：`jshERP-web/src/utils/scrollBlank.js`

**解决的问题**
1. 内容不足一屏时，不能出现可滚动空白。
2. 内容超出一屏时，上滑到底的底部留白 = 顶部基准留白（图一基准）。

**生效方式**

- **全局自动（默认）**：`main.js` 已调用 `installScrollBlank(router)`，所有页面在加载、路由切换、尺寸变化、内容变化、滚动停止后自动检测，页面无需任何接入代码。
- **显式接入（可选）**：需要指定首/尾元素时使用 `scrollBlankMixin`，此时全局自动模式让位。

**导出**

| 名称 | 说明 |
|---|---|
| `SCROLL_BLANK_MOBILE_MAX_WIDTH` | 手机断点，768 |
| `SCROLL_BLANK_VIEWPORT_VAR` | 可视高度变量名 `--scroll-blank-vh` |
| `syncScrollBlankViewport()` | 手机端写入 `innerHeight` 到变量并返回高度；桌面端移除变量返回 null |
| `detectScrollBlank(options)` | 检测并修正底部占位 |
| `scrollBlankMixin` | 显式接入方式：生命周期 + 自动重算 |
| `installScrollBlank(router)` | 全局安装（已在 `main.js` 调用），所有页面自动检测 |
| `refreshAutoScrollBlank()` | 手动触发一次全局检测，返回检测结果 |

**`detectScrollBlank(options)` 参数**

| 参数 | 必填 | 说明 |
|---|---|---|
| `first` | 是 | 首个内容元素 |
| `last` | 是 | 最后一个内容元素 |
| `bottomBar` | 否 | 固定底栏；缺省或找不到时按无底栏计算 |
| `topBar` | 否 | 固定顶栏，缺省取可见高度大于 0 的全局顶栏（`.ant-layout-header`，回退 `.header`） |
| `spacer` | 否 | 占位元素，传入时自动写入高度 |
| `gap` | 否 | 手动指定基准间距，缺省用实测 `topGap` |

**计算口径**

```
topGap          = round(docTop(first) − topBar.offsetHeight)        // 顶栏需贴在文档顶部
naturalHeight   = 文档高度 − spacer.offsetHeight
contentOverflow = naturalHeight − innerHeight > 1
spacerHeight    = contentOverflow ? max(0, barHeight + topGap − (naturalHeight − lastBottom)) : 0
bottomGap       = 文档高度 − lastBottom − barHeight
```

**返回**

```js
{ topGap, targetGap, bottomGap, spacerHeight, contentOverflow, balanced }
```

关键元素缺失或高度为 0 时返回 `null`。

#### 调用示例：页面完整接入

```html
<template>
  <div class="xxx-page">
    <div class="xxx-body">
      <div ref="scrollBlankFirst" class="xxx-card">…</div>

      <!-- 中间内容 -->

      <div ref="scrollBlankLast" class="xxx-card">…</div>

      <div ref="scrollBlankBottomBar" class="xxx-actions">
        <button class="primary">提交</button>
      </div>

      <div ref="scrollBlankSpacer" class="xxx-bottom-space"></div>
    </div>
  </div>
</template>
```

```js
import { scrollBlankMixin } from '@/utils/scrollBlank'
import { mixinDevice } from '@/utils/mixin'

export default {
  name: 'XxxPage',
  mixins: [mixinDevice, scrollBlankMixin],
  // 页面内不写任何空白计算逻辑
}
```

```css
@media (max-width: 768px) {
  .xxx-page {
    min-height: calc(100vh - 49px);                         /* 兜底：不支持 CSS 变量时 */
    min-height: calc(var(--scroll-blank-vh, 100vh) - 49px); /* 正常：JS 写入的可视高度 */
  }
  .xxx-actions {
    position: fixed;
    left: 0;
    right: 0;
    bottom: 0;
    padding: 12px 16px;
    padding: 12px 16px calc(12px + env(safe-area-inset-bottom));
    background: #fff;
    border-top: 1px solid #eee;
    z-index: 20;
  }
  .xxx-bottom-space {
    height: 80px;                                          /* 兜底 */
    height: calc(80px + env(safe-area-inset-bottom));
  }
}
```

#### 手动调用（一般不必要）

```js
mounted() {
  this.$nextTick(() => {
    const info = this.refreshScrollBlank()
    // info.balanced 为 true 表示上滑到底留白已与顶部一致
  })
}
```

#### 注意事项

1. 检测前必须先同步可视高度变量（`refreshScrollBlank` 内部已处理，不要自行调整顺序）。
2. 页面卸载必须移除 `--scroll-blank-vh`（mixin 已处理，不要绕过 mixin 手动设置）。
3. 仅适用于 window 整体滚动；内部容器滚动页面不适用。
4. 顶栏若不在文档顶部，`topGap` 会失真，需要显式传 `topBar`。

### 2.2 label-scroll —— 标签居中滑动与适配缩放

**文件**：`jshERP-web/src/utils/label-scroll.js`
**使用方**：`LabelEditMobile.vue`、`LabelEditModal.vue`

| 导出 | 说明 |
|---|---|
| `computeSpacer(labelDomWidth, zoom)` | 计算两侧等宽占位，保证标签可居中 |
| `centerScroll(wrapEl, vm, scrollingKey)` | 滚动至居中；`scrollingKey` 用于区分程序滚动与用户滚动 |
| `setupLabelScroll(vm, wrapRef, labelDomWidthKey, zoomKey, scrollingStateKey)` | 一次绑定滚动/缩放监听，页面只传 ref 与字段名 |
| `computeFitScale(paperW, paperH, containerW, containerH, padding, maxScale)` | 计算适配缩放比 |

```js
import { setupLabelScroll, computeFitScale } from '@/utils/label-scroll'

mounted() {
  this.setupScroll = setupLabelScroll(this, 'labelWrap', 'labelDomWidth', 'zoom', 'scrolling')
  this.zoom = computeFitScale(paperW, paperH, wrapW, wrapH, 16, 1)
}
```

**约束**：桌面端与手机端共用该模块，不要各自实现滚动居中；占位宽度必须由 `computeSpacer` 计算，保证两侧等宽。

## 5. 页面接入方式

### 5.1 默认：全局自动（无需任何页面代码）

模块已在 `src/main.js` 中全局安装：`installScrollBlank(router)`。**所有页面自动生效**，页面无需加 ref、无需引 mixin。

自动检测时机：

| 时机 | 触发方式 |
|---|---|
| 首次加载 | 安装时立即执行 + 300ms 后补测 |
| 路由切换 | `router.afterEach` 后立即 + 150ms 补测 |
| 窗口尺寸 / 横竖屏 | `resize` / `orientationchange`，120ms 去抖 |
| 内容变化（数据回填、图片加载、弹窗） | `ResizeObserver` + `MutationObserver`，60ms 去抖 |
| 滚动停止 | `scroll` 结束后 200ms |

自动定位规则：

1. 内容容器：从 `.ant-layout-content` 开始，逐层下钻“只有一个可见子元素”的包裹层（最多 4 层）。
2. 首/末元素：容器内第一个、最后一个可见且非固定定位的子元素（自动占位元素除外）。
3. 底栏：内容区内 `position: fixed` 且紧贴可视区底部的元素（BFS 最多 400 个节点）；找不到则按“无底栏”计算。
4. 占位：模块自动向容器末尾插入 `<div data-scroll-blank-spacer>`，高度由检测结果写入。

### 5.2 可选：显式接入 mixin

仅当自动定位不满足需求（例如需要指定特定首尾元素、或页面有多个固定底栏）时使用：

1. 模板加 4 个 ref：`scrollBlankFirst`、`scrollBlankLast`、`scrollBlankBottomBar`、`scrollBlankSpacer`。
2. 脚本 `mixins: [mixinDevice, scrollBlankMixin]`。
3. 手机端样式写双声明高度（`vh` 在前、`var` 在后）。
4. 底部占位给兜底高度（80px，含 `env()`）。

显式接入期间全局自动模式自动让位（`mixinDepth > 0`），不会产生双占位。当前地址识别页使用该方式。

### 5.3 公共要求

1. 手机端页面高度必须写双声明（见第 6.4 节）。
2. 页面不得自行创建占位元素或计算留白。
3. 真机验证 + 构建部署。

## 6. 强制规范（后续所有改动必须遵守）

### 6.1 可移植性

1. 不依赖特定系统或浏览器：禁止 `dvh`/`svh`/`lvh`、`visualViewport`、`-webkit-fill-available` 等。
2. CSS 双声明：标准值在前、增强值在后。例：`min-height: 100vh;` → `min-height: var(--scroll-blank-vh, 100vh);`。
3. JS 使用 `ResizeObserver` 等较新 API 前必须判断存在性，并提供降级路径。
4. 取值统一：尺寸 `getBoundingClientRect`/`offsetHeight`；视口 `innerHeight || clientHeight`；滚动 `pageYOffset || scrollTop`。

### 6.2 职责划分

5. 空白计算、占位修正只能写在 `utils/scrollBlank.js`；全局已对所有页面自动生效，页面**不得**再自行计算留白或插入占位元素。
6. 模块内不出现业务文案、接口调用、页面专有类名（全局顶栏缺省选择器除外）。
7. ref 命名固定，不得自定义别名。

### 6.3 改动纪律

8. 最小改动：只改与需求直接相关的代码，不顺手重构、不格式化无关文件。
9. 桌面端行为不变：新增手机端样式必须写在 `@media (max-width: 768px)` 内。
10. 注释使用中文，只解释「为什么」。
11. 每次改动必须构建通过并部署验证。
12. 全局顶栏高度（当前 49px）变更时，同步修改页面 `calc` 并复验上下留白。

### 6.4 布局规范

| 规则 | 写法 |
|---|---|
| 断点 | `@media (max-width: 768px)`，与 `SCROLL_BLANK_MOBILE_MAX_WIDTH` 一致 |
| 页面高度 | `calc(var(--scroll-blank-vh, 100vh) - 49px)`，前置 `calc(100vh - 49px)` |
| 全局布局高度 | `min-height: var(--scroll-blank-vh, 100vh) !important`，前置 `min-height: 100vh !important` |
| 固定底栏 | `position: fixed; bottom: 0`，`padding-bottom` 含安全区且带兜底 |
| 底部占位 | 保留兜底高度，实际高度由模块行内写入 |
| 不足一屏 | 占位为 0，不得有其它 `min-height` 撑高文档 |

###### 5.2 SKU 行表格列项（用户常问）

**不是全固定，分两部分：**

1. **固定 8 列**（写死在 `meTable.columns`）：
   `图片(image, hidden 上传)`、`进货价(purchaseDecimal)`、`划线价格(commodityDecimal)`、`价格(wholesaleDecimal)`、`最低售价(lowDecimal)`、`库存(stock)`、`仓库(depotId)`、`门店(store)`

2. **动态规格列**（`updateSkuColumns()` 生成）：
   - 规格模块有几个，就在「图片」列之后插入几列：`skuField1`、`skuField2`……，列名取规格名（如 颜色/规格/尺码），只读，宽度 10%
   - 规格模块来源：选中分类时读取该分类的 `specConfig`；分类未配置时给 1 个空白模块，可手动添加
   - 末尾追加 2 个 0 宽度隐藏列：`specValues`（规格值 JSON）、`sku`（SKU 组合文本），用于提交携带

3. **行数据生成**：规格值变化时按笛卡尔积重建行；已填的价格/库存等按 `sku` 组合文本回填保留。

###### 5.3 保存逻辑

- 基础信息按**字段键**提交并落库（输入框 key 即 DB 列名）。
- SKU 明细走 `meList`；`specValues` 和 `sku` 由隐藏列保证被 `JEditableTable` 收集，另有安全网在提交前从 `dataSource` 合并（防止隐藏列丢失）。
- SKU 码由后端统一生成（`generateSkuCode`），前端传的旧码会被忽略；同商品内规格组合重复会抛业务异常。

#### 商品表格模块化 + 列定义抽离 — 交接文档

> 适用范围：jshERP-web（Vue 2.7 + Ant Design Vue 1.5.2）

##### 1. 本次改造做了什么

把「商品 / SKU / 库存」相关的表格拆成两层：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 列定义层 | `src/views/material/config/materialColumns.js` | 唯一的列清单：标题、字段、宽度、显示方式、适用粒度、默认是否显示 |
| 展示逻辑层 | `src/views/material/utils/materialDisplay.js` | 唯一的单元格取值逻辑：图片地址、规格多行文本 |
| 组件层 | `src/components/material/MaterialTable.vue` | 通用表格组件，包一层 DataTable，内置图片/名称/规格/操作四个渲染器 |
| 使用层 | `src/views/material/MaterialList.vue` 等 | 只传数据 + 粒度 + 操作按钮，不再写列定义 |

改造前，商品信息页与「新增入库 → 选商品」各写了一份图片与规格显示代码，已出现不一致（100×80 圆角 12 vs 38×38 圆角 3、无图时「无图」vs 空白）。现在两处都指向同一份实现。

---

##### 2. 组件关系与数据流

```
MaterialList.vue                      （页面：查询条件、分页、权限、操作按钮）
   │  :dimension="spu|sku"  :actions="rowActions"  :data-source="tableRows"
   ▼
MaterialTable.vue                     （通用组件：列过滤 + 内置渲染器 + 插槽透传）
   │  :extra-columns  :default-columns  +  $attrs（bordered / table-key / pagination ...）
   ▼
DataTable/index.vue                   （本项目自研：列设置、列宽拖拽、固定列、汇总行）
   │  :columns  :data-source  :scroll
   ▼
a-table（Ant Design Vue）
```

要点：

- `MaterialTable` 把除 `columns / dimension / defaultColumns / actions` 之外的属性和事件**原样透传**给 `DataTable`（`v-bind="$attrs"` + `v-on="$listeners"`），所以 `bordered`、`row-key`、`table-key`、`storage-key`、`pagination`、`scroll`、`loading`、`row-selection`、`@change` 都在页面里直接写。
- 页面自定义插槽（如库存页的「修正库存」单元格）会被 `forwardSlotNames` 转发，内置插槽 `mtImage / mtName / mtSpec / mtAction` 不转发，避免重名覆盖。
- ⚠️ **不要在 `MaterialTable` 里给 `data-table` 加 `:data-source="xxx"`**，除非同时把 `dataSource` 声明为 prop。否则会把 `$attrs['data-source']` 覆盖成 `undefined`，表格直接空白。

##### 3. 列配置字段说明（materialColumns.js）

```js
{
  field: 'marketPrice',      // 接口返回字段名（后端 SQL 必须 select）
  title: '划线价',            // 表头文字，同时是列设置里的名称
  width: 80,                 // 列宽 px（建议每列都写，见第 7 节固定列）
  align: 'center',           // 可选：cell 对齐
  ellipsis: true,            // 可选：单行省略
  render: 'spec',            // 可选：显示方式，见 RENDER_SLOTS
  fixed: 'right',            // 可选：固定列（仅操作列使用）
  dimensions: ['sku', 'skuDepot'],  // 适用粒度
  defaultVisible: true,      // 可选：默认显示
  alwaysVisible: true        // 可选：列设置中禁止取消勾选
}
```

粒度取值：

| dimension | 含义 | 典型页面 |
| --- | --- | --- |
| `spu` | 一个商品一行（商品主表维度） | 商品信息页「单类显示」 |
| `sku` | 一个 SKU 一行 | 商品信息页「单品显示」、选商品弹窗 |
| `skuDepot` | SKU × 仓库 一行 | 库存页、库存报表 |
| 空字符串 | 不过滤，返回全部列 | 自定义场景 |

显示方式（`RENDER_SLOTS`）：

| render | 插槽 | 渲染内容 | 依赖的方法 |
| --- | --- | --- | --- |
| `image` | `mtImage` | `<img>` 100×80、圆角 12；无图显示「无图」 | `getRowImgUrl` |
| `spec` | `mtSpec` | 每个规格一行「规格名：规格值」，`white-space: pre-line` | `getSpecDisplay` |
| `name` | `mtName` | 商品名称 + 序/批 标签 | 无 |
| `action` | `mtAction` | 由 `actions` 数组渲染，`a-divider` 分隔，`show()` 控制权限 | 无 |
| 不填 | — | 纯文本 | 无 |

默认显示列的顺序由 `DEFAULT_ORDER` 决定；`defaultVisible: true` 但没写进 `DEFAULT_ORDER` 的字段会自动追加到末尾，不会丢列。

##### 4. 页面用法（以商品信息页为例）

```html
<material-table
  ref="table"
  bordered
  draggable
  row-key="skuRowKey"
  table-key="material_list"
  storage-key="columns_material"
  :dimension="displayMode"        <!-- 'spu' | 'sku' -->
  :actions="rowActions"
  :data-source="tableRows"
  :pagination="ipagination"
  :scroll="scroll"
  :loading="loading"
  :row-selection="{selectedRowKeys: selectedRowKeys, onChange: onSelectChange, columnWidth:'40px'}"
  @change="handleTableChange">
</material-table>
```

```js
rowActions() {
  const canEdit = this.btnEnableList.indexOf(1) > -1
  return [
    { title: '编辑', click: record => this.handleEdit(record) },
    { title: '复制', click: record => this.handleCopyAdd(record), show: () => canEdit },
    { title: '添加规格', click: record => this.handleAddSpec(record) },
    { title: '打印标签', click: record => this.handlePrintSkuLabel(record) }
  ]
}
```

操作列配置为 `fixed: 'right'`，横向滚动时固定在右侧。`DataTable` 只有在**所有列都有数值宽度**时才会设置 `scroll.x = 列宽之和`，固定列依赖这个 `scroll.x`，因此新增列务必写 `width`。

操作列宽度不再手写，由 `actionColumnWidth(actions)` 按按钮计算：

```
列宽 = Σ 单按钮宽度 + (按钮数 - 1) × 17（竖向分割线） + 20（约定留白）
单按钮宽度 = max(28, 标题字数 × 14)
```

例：`编辑 / 复制 / 添加规格 / 打印标签` → 28 + 28 + 56 + 56 + 3×17 + 20 = **239px**（内容 219 + 20）；
两个按钮（如 `编辑 / 删除`）→ 28 + 28 + 17 + 20 = **93px**。

配套约束：

- 操作列在 `buildTableColumns` 里打 `__lockWidth` 标记，`DataTable` 不会用配置中心 / localStorage 里的旧宽度覆盖它，也不渲染列宽拖拽手柄；
- 操作列单元格通过 `className: 'mt-action-col'` 把左右 `padding` 置 0，保证多出来的正好是那 20px；
- 页面只需要维护 `actions` 数组，增删按钮时列宽自动跟着变。

页面自带插槽时直接写在 `<material-table>` 内即可，例如：

```html
<material-table ...>
  <template slot="currentStock" slot-scope="text, record">...</template>
</material-table>
```

（`currentStock` 是列配置里 `render` 之外的字段名，DataTable 会用它做 `customRender`。）

##### 9. 注意事项 / 已踩过的坑

1. **图片路径含 `[`**：不能走 `getFileAccessHttpUrl`（会过滤掉），必须用 `materialDisplay.js` 的 `getSkuImgUrl`，并补 `systemConfig/static/` 前缀。
2. **规格多行不生效**：容器必须是 `white-space: pre-line`，且该列不能加 `ellipsis`。
3. **固定列失效**：`DataTable` 在任一列缺少数值宽度时不设置 `scroll.x`，`fixed: 'right'` 会退化成普通列。
4. **最后一列被拉伸 / 竖线错位**：列宽总和小于容器宽度时，`DataTable` 会自动追加一列空白填充列（`className: 'dt-filler-col'`），插在固定右列之前；不要在业务列里手工补空列。列设置把数据列排到操作列之后时，固定右列会被强制移回最后。
5. **表格空白**：检查是否在 `MaterialTable` 内重复写了 `:data-source`；检查 `data-source` 是否传了 `undefined`。
6. **列设置刷新后全部显示**：历史上带 `tableKey` 的表格没写存储键，或单列勾选时逗号判断失效，已在 `DataTable` 修过，改动时不要回退该逻辑。
7. **Vue 模板不能直接调用 import 的函数**：`MaterialTable` 内已封装成 method（`resolveImg` / `resolveSpec`）。
8. **修改后需重启/等待编译**：`npm run serve` 热更新即可；后端改了 mapper 必须重启。

#### 页面滚动空白检测 — 交接文档

> 编写日期：2026-11-08
> 涉及模块：`jshERP-web`（前端）
> 关键文件：
> - `jshERP-web/src/utils/scrollBlank.js`（通用模块，新增）
> - `jshERP-web/src/views/system/AddressRecognize.vue`（首个接入页面）
> - `jshERP-web/src/components/page/GlobalLayout.vue`（全局布局高度变量）
>
> 本文档同时作为**后续所有代码改动的强制规范**，新增或修改代码必须遵守第 6 节。

---

##### 1. 需求约定（已确认）

适用场景：手机端「固定顶栏 + 固定底栏 + 页面整体滚动」的页面。首个落地页面为「地址识别」页。

| 序号 | 约定 | 落地方式 |
|---|---|---|
| 1 | 内容区第一个组件到顶栏底边的距离为**基准间距**（以图一输入框到顶栏的距离为准） | 运行时测量，不写死像素 |
| 2 | 上滑到底时，最后一个组件到底栏顶边的距离**等于**基准间距，到达后不再继续上滑 | 动态设置底部占位高度 |
| 3 | 内容不足一屏时不额外占位，不产生可滚动空白 | 占位归零 + 页面高度按实测可视高度计算 |
| 4 | 空白检测逻辑**抽离为通用模块**，页面只挂 ref 使用 | `scrollBlankMixin` + 约定 ref |

范围：仅手机端（`max-width: 768px`）生效；桌面端保持原样。

---

##### 2. 方案总览

三个机制配合，缺一不可：

```
① 可视高度变量：JS 读 window.innerHeight → 写入 --scroll-blank-vh
        ↓（解决：iOS 等浏览器 100vh 大于可视高度导致的可滚动空白）
② 基准间距测量：首元素顶边 − 顶栏底边 = topGap（图一基准）
        ↓
③ 底部占位修正：内容超出一屏时，占位高度 = 底栏高 + topGap − 内容自然底部留白
        ↓（解决：上滑到底末元素被底栏遮挡，或多滑出空白）
```

三者由 `scrollBlankMixin` 在挂载、内容变化、窗口尺寸变化时统一重算。

---

##### 3. 通用模块 API

文件：`jshERP-web/src/utils/scrollBlank.js`

###### 3.1 导出清单

| 导出 | 类型 | 说明 |
|---|---|---|
| `SCROLL_BLANK_MOBILE_MAX_WIDTH` | `number` | 手机断点，默认 `768` |
| `SCROLL_BLANK_VIEWPORT_VAR` | `string` | 可视高度 CSS 变量名，`--scroll-blank-vh` |
| `syncScrollBlankViewport()` | `function` | 同步可视高度到 CSS 变量 |
| `detectScrollBlank(options)` | `function` | 纯检测 + 修正占位，返回检测结果 |
| `scrollBlankMixin` | `Object` | 页面级 mixin，负责生命周期与自动重算 |

###### 3.2 页面 ref 约定（命名不可随意更改）

| ref 名 | 必填 | 指向 |
|---|---|---|
| `scrollBlankFirst` | 是 | 内容区**第一个**元素（决定基准间距） |
| `scrollBlankLast` | 是 | 内容区**最后一个**元素（决定上滑到底位置） |
| `scrollBlankBottomBar` | 是 | 固定底栏（决定占位高度） |
| `scrollBlankSpacer` | 否 | 底部占位元素，高度由模块写入 |
| `scrollBlankTopBar` | 否 | 固定顶栏，缺省取全局 `.ant-layout-header` |

###### 3.3 `syncScrollBlankViewport()`

- 手机端：把 `window.innerHeight`（兜底 `documentElement.clientHeight`）写入 `<html>` 的 `--scroll-blank-vh`，返回该高度。
- 非手机端：移除该变量，返回 `null`。

###### 3.4 `detectScrollBlank(options)`

参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `first` | 是 | 首元素 |
| `last` | 是 | 末元素 |
| `bottomBar` | 是 | 固定底栏 |
| `topBar` | 否 | 固定顶栏，缺省取可见高度大于 0 的全局顶栏（`.ant-layout-header`，回退 `.header`） |
| `spacer` | 否 | 占位元素，传入时自动写入高度 |
| `gap` | 否 | 手动指定基准间距，缺省用实测 `topGap` |

计算规则：

```
topGap        = round(docTop(first) − topBar.offsetHeight)      // 前提：顶栏贴在文档顶部
lastBottom    = docBottom(last)
naturalHeight = 文档高度 − spacer.offsetHeight                   // 剔除占位后的真实内容高度
contentOverflow = naturalHeight − innerHeight > 1
spacerHeight  = contentOverflow
              ? max(0, round(barHeight + topGap − (naturalHeight − lastBottom)))
              : 0
bottomGap     = 文档高度 − lastBottom − barHeight                // 占位生效后上滑到底的实际留白
```

返回值：`{ topGap, targetGap, bottomGap, spacerHeight, contentOverflow, balanced }`；关键元素缺失或高度为 0 时返回 `null`。

###### 3.5 `scrollBlankMixin`

| 钩子 | 行为 |
|---|---|
| `mounted` | 绑定 `resize` / `orientationchange`，创建 `ResizeObserver` 监听首尾元素，`$nextTick` 首次检测 |
| `activated` | keep-alive 激活时重新检测 |
| `updated` | 每次 DOM 更新后重新检测（结果相同则不重复赋值） |
| `beforeDestroy` | 移除事件、断开观察器、移除 `--scroll-blank-vh` |

对外方法：`refreshScrollBlank()`（手动重算并返回结果）、`observeScrollBlank()`（重新监听 ref）、`resetScrollBlank()`（非手机端恢复占位）。
对外数据：`scrollBlankInfo`（最近一次检测结果，不参与渲染，避免触发更新循环）。

###### 3.6 使用约束

1. `refreshScrollBlank()` 内部**先**同步可视高度变量，再测量；顺序不可调换，否则测量基于错误的页面高度。
2. `updated` 中赋值 `scrollBlankInfo` 前必须经 `isSameBlankInfo` 去重，防止循环更新。
3. 内容不足一屏时 `spacerHeight = 0`，且不得有其他 `min-height` 把文档撑高。
4. 页面卸载时必须移除 `--scroll-blank-vh`，否则会影响其他页面（变量挂在 `<html>` 上）。
5. 该模块只适用于**window 整体滚动**的页面；若页面是内部容器滚动，不适用。

##### 6. 强制编码规范（后续所有改动遵循）

**可移植性**

1. 不依赖特定操作系统或浏览器特性，禁止使用 `dvh`/`svh`/`lvh`、`visualViewport`、`-webkit-fill-available` 等非通用方案。
2. 必须写“标准值在前、增强值在后”的双声明：`vh` → `var(--scroll-blank-vh, 100vh)`；`padding` → `calc(... + env(...))`。使不支持新特性的环境自动回退，而不是布局塌陷。
3. JS 只用通用 API；使用 `ResizeObserver` 等较新 API 前必须做存在性判断，并提供降级路径（如 `updated` 钩子兜底）。
4. 读取尺寸/位置统一用 `getBoundingClientRect`、`offsetHeight`；读视口统一用 `innerHeight || documentElement.clientHeight`；读滚动统一用 `pageYOffset || documentElement.scrollTop || body.scrollTop`。

**职责划分**

5. 空白计算、占位修正只允许写在 `utils/scrollBlank.js`；页面只允许挂 ref、引入 mixin、写样式。
6. 模块内不出现业务文案、接口调用、页面专有类名（`.ant-layout-header` 除外，作为全局顶栏缺省值）。
7. ref 命名必须沿用 `scrollBlankFirst` / `scrollBlankLast` / `scrollBlankBottomBar` / `scrollBlankSpacer` / `scrollBlankTopBar`。

**改动纪律**

8. 最小改动：只改与需求直接相关的代码，不顺手重构、不格式化无关文件。
9. 桌面端行为不得改变；所有新增手机端样式必须写在 `@media (max-width: 768px)` 内。
10. 注释使用中文，只解释“为什么”，不复述代码。
11. 每次改动后必须本地构建通过（`npm run build`）并部署验证，不提交无法构建的代码。
12. 若全局顶栏高度调整，必须同步修改页面 `calc(... - 49px)`，并重新验证上下留白。

| `applyProviderData(provider, rebuild)` | 并行加载字段与数据，重建 `allAttrs`，保留已选字段样式 |
| `buildAttrs(builder)` | 按业务构建默认字段集合 |
| `buildLabelAttrs / buildDeliveryAttrs / buildReceiptAttrs / buildMemberAttrs` | 各业务字段定义 |
| `applyDefaultLayout(cfg)` | 无模板时按 `cfg.defaultKeys` 生成初始布局 |
| `applyTemplateSnapshot(snap, cfg)` | 把持久化模板应用到编辑状态（`selectedAttrs`/`attrStyles`/`attrLabels`/尺寸） |
| `restoreMissingAttrs(keys)` | 模板中存在但当前字段集没有的 key 补空字段，保证可渲染 |
| `openSizeEditor / confirmSizeEdit` | 尺寸编辑，毫米 ↔ 像素（`PX_PER_MM = 3.779528`） |

###### 3.4 保存时序

```
保存按钮
  └─ saveTemplate()
       ├─ storage = localTemplates（商品）
       │    ├─ 命名弹窗 → confirmSaveTemplate()
       │    ├─ buildTplPayload() 组装模板对象
       │    └─ persistTemplate() → saveLabelTemplate() → POST /labelTemplate/save
       │         └─ 成功：fetchLabelTemplates() 刷新列表，回填 serverId / selectedTemplateId
       └─ storage = deliveryTemplate / platformConfig
            └─ persistUnifiedTemplate(cfg, name)
                 ├─ deliveryTemplate：persistDeliveryTemplate() → 发货单模板适配器
                 └─ platformConfig：postSnapshot(key, payload) → POST /platformConfig/saveUiConfig
```

失败处理：云端保存失败时提示「模板已保存到本机，云端保存失败」，不阻断编辑。

###### 3.5 打印页初始化时序

```
created()（/label/print-mobile）
  ├─ type = query.type（默认 delivery）
  ├─ allAttrs = buildAttrList()
  └─ loadRouteTemplate(query)
       ├─ label      → fetchLabelTemplates()，按 templateId 或首个模板
       ├─ delivery   → fetchDeliveryTemplate()
       ├─ receipt    → getUiConfig('receipt_layout')
       ├─ member     → getUiConfig('member_layout')
       └─ address    → getUiConfig('address_layout')
            ↓
     normalizeTemplate(raw)
       ├─ v3 schema → schemaToLegacy()
       ├─ 补 name / businessType / 默认尺寸（320×240 / 560×800 / 380×600 / 320×240；address 320×240）
       └─ 校验 selectedAttrs 非空，否则返回 null
            ↓
     applyTemplate(tpl) → restoreMissingAttrs() → applySnapshotValues()
       └─ 从 sessionStorage['jsh.labelEdit.snapshot'].values 回填业务值
```

无模板时：

- 显示 `emptyMessage`（会员为「暂无可用会员标签模板」）
- 会员类型且为路由页时，页面中间显示「创建会员标签模板」按钮
  → `handleCreateTemplate()`：写入 `jsh.labelEdit.context` → 跳转编辑页

###### 4.5 数据源契约（后端）

业务表注册（`LabelProviderRegistry.BUSINESS_TABLES`）：

| `businessType` | 可用数据表 |
| --- | --- |
| `product` | 商品内置 provider（`product.label`） |
| `delivery` | `jsh_depot_head`（销售出库主表）、`jsh_depot_item`（明细表）、`jsh_supplier`（会员信息表） |
| `member` | `jsh_supplier`（会员信息表） |

- provider 命名：内置 `product.label`、`sales.delivery`；动态表 `table.<表名>`（如 `table.jsh_supplier`）
- 取数 SQL：按「`businessType:表名`」优先匹配 `TABLE_LOAD_SQL`，未传 `businessType` 时按表名兼容旧逻辑
  - `delivery:jsh_supplier`：通过 `jsh_depot_head.organ_id = jsh_supplier.id` 关联取会员
  - `member`：直接 `SELECT * FROM jsh_supplier WHERE id = ?`
  - 其它表：默认按主键 `id` 查询单条
- 字段元数据来自 `information_schema`（列名、注释、类型）：**字段 key = 数据库列名**
  - 例如会员：`contacts`、`telephone`、`phone_num`、`address`、`advance_in`、`description`、`enabled`
  - 注意不能用实体驼峰名（`phoneNum`/`advanceIn`）做绑定 key
- 接口：

| 方法 | 地址 | 参数 | 返回 |
| --- | --- | --- | --- |
| GET | `/labelProvider/list` | `businessType` | 数据表清单 `[{ provider, name, ... }]` |
| GET | `/labelProvider/fields` | `provider` | 字段清单 `[{ key, label, comment, type }]` |
| GET | `/labelProvider/data` | `provider`、`documentId`、`subId?`、`businessType?` | 列名 → 值 |

###### 4.6 sessionStorage 快照

| key | 结构 | 写入方 | 读取方 |
| --- | --- | --- | --- |
| `jsh.labelEdit.context` | `{ record, sku, template, provider, businessType }` | 打印页 `handleEdit/handleCreateTemplate`、业务页入口 | 编辑页 `initFromRoute`（读取后删除） |
| `jsh.labelEdit.snapshot` | `{ labelWidth, labelHeight, selectedAttrs, attrStyles, attrLabels, values }` | 编辑页 `handlePrint`、打印页/会员预览跳转前 | 打印页 `applySnapshotValues` |

`values` 为「字段 key → 值」映射，key 必须与模板 `selectedAttrs` 一致（即数据库列名）。

##### 5. 保存

###### 5.1 存储对照

| 类型 | 存储介质 | 写入接口 | 数据形态 |
| --- | --- | --- | --- |
| 商品标签 | `print_template` 表 | `POST /labelTemplate/save` | 单条模板记录，返回 `serverId`；`type=normal` 普通、`type=default` 类型通用 |
| 发货单 | 发货单模板适配器（统一存储，兼容旧 platformConfig） | `persistDeliveryTemplate()` | 单套模板，`businessType='shipping.delivery'` |
| 小票 | `jsh_platform_config` | `POST /platformConfig/saveUiConfig` | `key='receipt_layout'`，`value=JSON` |
| 会员标签 | `jsh_platform_config` | `POST /platformConfig/saveUiConfig` | `key='member_layout'`，`value=JSON` |
| 地址打印 | `jsh_platform_config` | `POST /platformConfig/saveUiConfig` | `key='address_layout'`，`value=JSON`（独立于会员标签） |

###### 5.2 商品模板保存

1. `buildTplPayload()`：收集 `selectedAttrs`、仅保留已选字段的 `attrStyles`/`attrLabels`、`customLabels`、尺寸、provider/businessType
2. 命名弹窗确认：不选商品类型 → 普通模板；选择类型 → 该类型通用模板（同类型只保留一份）
3. `saveLabelTemplate()` → `POST /labelTemplate/save`
4. 成功后 `fetchLabelTemplates()` 刷新，按 `serverId` 回填 `selectedTemplateId`

###### 5.3 发货单保存

`persistUnifiedTemplate()` → 组装 `{ name, businessType: 'shipping.delivery', provider, selectedAttrs, attrStyles, attrLabels, labelWidth, labelHeight }` → `persistDeliveryTemplate()` → 返回主键写回 `deliveryTemplate.serverId/id`。

###### 5.4 小票 / 会员保存

`persistUnifiedTemplate()` → `postSnapshot(cfg.platformConfigKey, payload)`：

```js
POST /platformConfig/saveUiConfig
{
  key: 'member_layout',
  value: '{"name":"会员标签模板","selectedAttrs":["contacts","telephone"],"attrStyles":{},"attrLabels":{},"width":320,"height":240}'
}
```

单 key 覆盖写，重复保存直接替换，不做版本留档。

###### 5.5 保存后行为

- 成功：`showSaveResult()` 按 `cfg.successMsg` 提示
- 编辑页「打印」：`handlePrint()` 把当前布局与字段值写入 `jsh.labelEdit.snapshot`，跳转 `/label/print-mobile?type=<type>`（商品标签额外带 `templateId`、`name`）
- 打印页读取同类型模板 + 快照值渲染预览，然后打印

###### 5.6 失败处理

- 云端保存失败：提示「模板已保存到本机，云端保存失败，其他设备暂无法同步」，保留本地编辑态
- 加载失败：回退默认布局（`applyDefaultLayout`），不阻塞编辑

##### 6. 后端接口汇总

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/labelProvider/list` | GET | 按 `businessType` 返回可用数据表 |
| `/labelProvider/fields` | GET | 返回指定 provider 的字段元数据 |
| `/labelProvider/data` | GET | 按业务单据 id 取数据，`businessType` 决定取数 SQL |
| `/labelTemplate/list` | GET | 统一模板表列表 |
| `/labelTemplate/save` | POST | 保存商品模板，返回 `serverId` |
| `/platformConfig/getUiConfig` | GET | 读取单 key 模板配置（小票/会员/发货单） |
| `/platformConfig/saveUiConfig` | POST | 覆盖写单 key 模板配置 |

##### 7. 新增业务类型接入清单

1. 后端 `LabelProviderRegistry.BUSINESS_TABLES` 注册业务表；需要特殊取数时按 `businessType:表名` 写入 `TABLE_LOAD_SQL`
2. 前端 `TYPE_CONFIG` 增加类型：标题、默认尺寸、attrsBuilder、storage、platformConfigKey、defaultKeys
3. `buildAttrs()` 增加分支并实现 `buildXxxAttrs()`（key 用数据库列名，值取业务对象字段）
4. `businessType` 兜底映射、`initProvider` 的默认 provider、字段分组 `group`
5. 打印页 `pageTitle`、`emptyMessage`、`normalizeTemplate` 默认尺寸
6. 打印页 `loadRouteTemplate` 增加模板读取分支
7. 入口页面写入 `jsh.labelEdit.snapshot`（values）与 `jsh.labelEdit.context`（record/provider/businessType）
8. 无模板时提供创建入口（参考会员：`handleCreateTemplate`）
9. 保存链路按 storage 选择：多模板走 `/labelTemplate/save`，单模板走 `platformConfig`

##### 8. 注意事项

- **字段 key 必须使用数据库列名**（下划线），不能用 Java 实体驼峰名，否则模板绑定取不到值
- `provider` 与 `businessType` 必须成对传递；同一张表在不同业务下取数 SQL 可能不同（如 `jsh_supplier`）
- 模板只保存布局与字段绑定，不保存业务数据；打印值来自页面快照或实时接口
- `sessionStorage` 上下文为一次性，编辑页读取后即删除；快照仅服务本次打印
- `platformConfig` 模板为单份覆盖写，不保留历史版本
- 模板渲染前先 `normalizeTemplate`，兼容 v3 elements、旧配置、编辑器快照三种来源
- 手机端页面高度使用 `dvh`，中部内容区独立滚动，底部操作栏固定
- 挂载到 `document.body` 的弹层（a-drawer/a-modal）样式需使用非 scoped 全局类名

###### 2.3 识别接口 `/material/scanFrame`（拍照兜底路径）

使用 ZXing 生成标准测试图（PNG → base64 → POST）实测。

| 测试图 | 编码内容 | 返回 `format` | 返回 `type` | 返回内容 |
| --- | --- | --- | --- | --- |
| 二维码 | `QR-TEST-ABC-2026-01` | `QR_CODE` | `2D` | 与输入完全一致 |
| 二维码（前导零） | `0001234567890` | `QR_CODE` | `2D` | `0001234567890`（前导零保留） |
| 一维码 | `ABC-00123-99` | `CODE_128` | `1D` | 与输入完全一致 |
| 一维码 | `CODE39-TEST-01` | `CODE_39` | `1D` | 与输入完全一致 |
| 一维码（前导零） | `0001234567895` | `UPC_A` | `1D` | `001234567895` |

位置信息同时返回：二维码框 `(166,166,308,308)`，一维码框 `(59,119,770,21)`。

**已知格式歧义（ZXing 固有行为，非本系统改写）**：以 `0` 开头的 13 位 EAN-13 符号在编码层面同时满足 UPC-A 定义，`GenericMultipleBarcodeReader` 会按 UPC-A 输出 12 位（少 1 位前导 0）。同一张图用单码阅读器可解出 `EAN_13` / `0001234567895`。前端实时扫描路径的提示格式顺序为 `EAN_13` 优先于 `UPC_A`，正常情况下返回 13 位；拍照兜底路径存在上述歧义。

##### 三、识别准确率（合成样本）

| 指标 | 数值 |
| --- | --- |
| 样本数 | 4（QR_CODE ×2、CODE_128 ×1、CODE_39 ×1，含 1 张前导零 EAN-13） |
| 单码阅读器解出 | 4 / 4（100%） |
| 内容完全一致 | 4 / 4（100%，含前导零 EAN-13 单码路径） |
| 多码阅读器解出 | 4 / 4（100%） |
| 多码阅读器内容完全一致 | 3 / 4（75%，EAN-13 被识别为 UPC-A） |

样本为程序生成的标准码图，不代表真实摄像头拍摄（光照、角度、污损、曲面）条件下的准确率。

##### 四、浏览器兼容性

**未进行真机/浏览器实测**，以下仅为代码层面的能力依赖分析：

| 能力 | 依赖 | 现状 |
| --- | --- | --- |
| 实时扫码 | `navigator.mediaDevices.getUserMedia`、`decodeFromConstraints` | 需 HTTPS 或 localhost；非安全源直接降级为拍照模式 |
| 后置摄像头 | `facingMode: environment` / `deviceId` 枚举 | Chrome/Edge/Android 支持；iOS Safari 以设备枚举切换为主 |
| 手电筒 | `MediaStreamTrack.getCapabilities().torch` + `applyConstraints` | Android Chrome 通常支持；iOS Safari 一般不支持，界面自动隐藏按钮 |
| 拍照兜底 | `<input type=file capture=environment>` + 后端识别 | iOS/非 HTTPS 场景可用 |
