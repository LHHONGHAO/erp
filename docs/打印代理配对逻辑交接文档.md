# 打印代理「配对逻辑」交接文档

> 状态：**该配对方案已全部下线**（2026-11-14）。本文档保存原设计、协议细节与下线影响，供后续需要恢复或复盘时使用。
> 现行做法见文末「当前替代方案」。

---

## 1. 背景

打印代理（`erp-print-agent`，Go 编写，部署在 OpenWrt 路由器上）不在 ERP 的登录体系内，需要通过 WebSocket 接入 ERP 接收打印任务：

- 代理 → ERP：`wss://<erp-host>:<port>/ws/print-agent`
- 握手头：`Authorization: Bearer <token>`、`X-Device-Id: <deviceId>`
- 设备台账存于 MySQL 表 `print_agent`

配对逻辑要解决的问题是：**设备首次接入时如何自动获取 Token 和服务端地址**，避免用户手工在代理里填一长串 Token。

---

## 2. 原配对流程（时序）

```
代理本机                     用户                      ERP 打印管理页                 ERP 后端
   │                          │                            │                        │
   │ 生成 deviceId + 配对码    │                            │                        │
   │─── 显示在本机页/LuCI ───→ │                            │                        │
   │                          │ 填写 deviceId + 配对码       │                        │
   │                          │───────────────────────────→ │ POST /printAgent/pair/prepare
   │                          │                            │──────────────────────→ │ 记录配对码(10 分钟有效)
   │                          │                            │ ←── {pairExpireAt} ──── │ 断开该设备旧连接
   │ POST /printAgent/device/pair {deviceId, pairCode}      │                        │
   │──────────────────────────────────────────────────────────────────────────────→ │ 校验配对码
   │ ←──────── {token, serverUrl, serverName, heartbeatSeconds, printers} ───────── │ 置 paired=1，清空配对码
   │ 保存 token/serverUrl，建立 WebSocket 连接               │                        │
   │                          │  轮询 GET /pair/status      │                        │
   │                          │ ←── paired=1 / online=true ─│                        │
   │ 每 6 小时 POST /printAgent/device/refresh（换发新 Token）│                        │
```

要点：

1. **配对码由设备端生成并展示**，用户在 ERP 页面录入；ERP 只负责登记与校验，不主动下发配对码。
2. 配对码有效期 **10 分钟**，一次性使用，配对成功后立即清空。
3. 配对成功即返回 `serverUrl`，代理无需再手工配置服务端地址。
4. 旧 Token 在重新配对时立即作废，并在配对成功/吊销时主动关闭该设备的在线连接。

## 3. 数据结构（print_agent 表）

配对期新增过以下 8 个列（**现已全部 DROP**）：

| 列名 | 类型 | 含义 |
| --- | --- | --- |
| `paired` | varchar(1) | 0 待配对 / 1 已配对 |
| `revoked` | varchar(1) | 0 正常 / 1 已吊销 |
| `pair_code` | varchar(32) | 一次性配对码 |
| `pair_expire_at` | datetime | 配对码过期时间 |
| `server_url` | varchar(255) | 代理应连接的 WebSocket 地址 |
| `token_expire_at` | datetime | 当前 Token 过期时间（30 天） |
| `prev_token` | varchar(64) | 上一次 Token（续期宽限用） |
| `prev_expire_at` | datetime | 上一次 Token 过期时间（1 天） |

`PrintAgentStore.ensureAgentColumns()` 会在启动时做幂等补列，并把 `token` 非空的旧设备回填为 `paired='1'`，保证升级平滑。

## 4. 接口清单

### 4.1 页面侧（需 ERP 登录态）

| 方法 | 路径 | 请求 | 响应 |
| --- | --- | --- | --- |
| POST | `/printAgent/pair/prepare` | `{deviceId, pairCode}` | `{deviceId, pairExpireAt}`；配对码 10 分钟有效 |
| GET | `/printAgent/pair/status?deviceId=` | - | `{deviceId, paired, revoked, pairExpireAt, online}`；设备不存在返回 404 |
| POST | `/printAgent/revoke` | `{deviceId}` | `ok`；清空 Token/配对码，`revoked=1`，断开连接 |

`pair/prepare` 行为细节：

- 设备不存在 → 新建记录（`paired='0'`、`token=NULL`、`printers='[]'`）；
- 设备已存在 → 覆盖配对码、清空 Token 与续期字段、`paired='0'`、`revoked='0'`、`enabled='1'`；
- 若设备当前离线连接存在，会被主动关闭，迫使代理重新配对。

### 4.2 设备侧（免登录，白名单）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/printAgent/device/pair` | 配对码 | 用 `{deviceId, pairCode}` 换取 Token |
| POST | `/printAgent/device/refresh` | `Bearer <token>` + `X-Device-Id` | 换发新 Token，建议周期 6 小时 |

`/device/pair` 成功响应：

```json
{
  "deviceId": "agent-abcd1234",
  "token": "32 位十六进制",
  "serverUrl": "wss://erp.example.com:9999/ws/print-agent",
  "serverName": "erp.example.com",
  "heartbeatSeconds": 21600,
  "printers": [ ... ]
}
```

- `serverUrl` 推导：优先 `X-Forwarded-Proto` / `X-Forwarded-Host`，否则用请求的 scheme + host + port，固定路径 `/ws/print-agent`。
- `serverName`：去掉端口的主机名，用于 TLS 证书 SAN 校验。
- 失败返回 400 + 可读原因（配对码错误、过期、设备停用、已吊销等）。

`/device/refresh` 校验通过后：`prev_token` 置为旧 Token 并给 1 天宽限，`token` 换新，`token_expire_at` 顺延 30 天。这样即使续期响应丢失，旧 Token 仍能继续连接，不会把设备锁死。

### 4.3 Token 校验状态机（`checkToken`）

```
不存在        → not_registered
revoked='1'   → revoked
enabled='0'   → disabled
paired='0'    → pending
token 既不等于 token 也不等于 prev_token → wrong_token
token/prev_token 匹配但已过期 → expired
否则 → ok
```

WebSocket 握手与 `/device/refresh` 共用这套判定。

## 5. 安全设计

- 配对码 10 分钟过期、一次性；仅能换取本设备的 Token。
- Token 有效期 30 天，续期通过设备自身 Token 鉴权，不依赖用户登录。
- `prev_token` 1 天宽限，容忍续期请求丢失/重放。
- 设备停用（`enabled='0'`）与吊销（`revoked='1'`）都会立即拒连，并断开现有会话。
- 白名单：`LogCostFilter` 中 `/printAgent/device#` 前缀免登录，鉴权完全依赖配对码/Token；**其余 `/printAgent/*` 仍需 ERP 登录态**。

## 8. 当前替代方案（现状）

手工登记 + 直接 Token 鉴权：

1. 在 ERP「打印管理」新增设备，系统自动生成 32 位 Token（也可「重置 Token」）；
2. 把页面上的 **设备编号** 与 **Token** 填到路由器 LuCI「远程打印」页（或直接写 `/etc/erp-print-agent/config.json`），或复制到代理配置；
3. 保存后重启服务，代理用 `X-Device-Id` + `Bearer <token>` 握手；
4. 握手逻辑：设备不存在 / `enabled='0'` → 403；Token 不匹配 → 401；
5. 需要让设备失联时，在 ERP 停用设备或重置 Token 即可。

`print_agent` 现存列：`id, device_id, name, token, printers, version, last_seen, client_ip, enabled, created_at, updated_at`。

## 9. 如需恢复配对能力

1. 先补列（与 `PrintAgentStore` 建表语句保持一致），并回填 `paired='1' WHERE token IS NOT NULL AND token <> ''`；
2. 恢复页面侧三个接口与设备侧两个接口，注意 `/printAgent/device#` 重新加入白名单；
3. 握手逻辑从「直接比对」改回 `checkToken` 状态机，以支持过期/宽限/吊销语义；
4. 前端补配对入口与轮询；代理补配对请求、`UpdateAuth` 热切换与 6 小时续期；
5. 代理配置允许 `token` 为空 + 存 `pairCode`，首次配对成功后写回 `config.json`。

## 10. 排障速查

| 现象 | 排查方向 |
| --- | --- |
| 握手 401 | `print_agent.token` 与代理配置不一致；重置 Token 后未同步到代理 |
| 握手 403 | 设备未登记，或 `enabled='0'` |
| 代理反复重连 | ERP 地址/端口/证书问题；`serverName` 与证书 SAN 不匹配 |
| 配对码「一直无效」 | 设备与 ERP 服务器时间不同步（过期判定用 MySQL `NOW()`），先在路由器上确认 NTP |
| 页面显示在线但打印无响应 | 查 `print_task` 状态与代理日志（p910nd 9100 是否可达） |
| LuCI 页面报 `unfinished string` | 模板 `index.htm` 被保存成 CRLF；LuCI 模板解析器只接受 LF（打包脚本已强制转换） |

日志关键字：

- ERP：`打印代理鉴权失败`、`打印代理配对成功`、`打印代理设备表 print_agent 已就绪`
- 代理：`已连接云端 ERP`、`本机管理页`（已下线，不应再出现）、`打印机 default(127.0.0.1:9100) 端口可达`
