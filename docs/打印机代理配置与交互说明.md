# 打印机 / 打印代理 配置与交互说明

> 对应代码状态：主机「打印管理」按配对码接入 + 代理 LuCI 设置页。
> 旧的通信码、设备配置弹层、主机侧测试打印均已移除；本地测试打印在代理设置页。

## 1. 角色与组件

| 角色 | 位置 | 职责 |
| --- | --- | --- |
| ERP 前端 | `jshERP-web/src/views/print/agent/PrintAgentList.vue` | 设备列表、生成配对码、任务记录 |
| 标签打印前端 | `jshERP-web/src/views/material/modules/LabelPrintModal.vue` | 选择远程打印机、发起打印 |
| 打印机配置前端 | `jshERP-web/src/views/print/agent/PrinterDeviceConfig.vue` | 选择品牌/指令集，调用 `/printAgent/save` |
| ERP 后端 | `jshERP-boot/src/main/java/com/jsh/erp/print/` | 配对、设备台账、WebSocket 收发、任务调度、记录 |
| 打印代理 | `erp-print-agent/`（Go） | 连接主机、接收任务、直写打印机 |
| 代理设置页 | `erp-print-agent/packaging/openwrt/luci/` | LuCI 菜单「服务 → 远程打印」 |

职责边界：**通信地址、配对码、门店、型号、打印机列表由代理端填写**；主机只负责生成配对码、分配设备编号与 Token、查看状态和下发打印任务。

## 2. 数据模型

### 2.1 主机表 `print_agent`

启动时自动建表，并按需补列（存量设备不回退）。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键 |
| `device_id` | 设备编号，配对时由主机生成：`agent-` + 6 位字符（去掉易混字符） |
| `name` | 设备名称（可空，历史字段） |
| `store_name` | 门店名称，代理配对时上报，主机可改 |
| `printer_model` | 打印机型号，代理配对时上报 |
| `token` | 32 位 Token（UUID 去横线），握手鉴权用 |
| `paired` | `1` 已配对；`0` 待配对（仅历史数据） |
| `printers` | 打印机数组 JSON，见 2.2 |
| `enabled` | `1` 启用；`0` 停用，停用后握手返回 403 |
| `version` / `client_ip` | 代理版本、最近连接 IP |
| `last_seen` | 最近上报时间 |
| `created_at` / `updated_at` | 时间戳 |

### 2.2 `printers` 元素

```json
{
  "id": "default",
  "name": "标签打印机",
  "host": "192.168.10.10",
  "port": 9100,
  "enabled": true,
  "cmdSet": "TSPL",
  "brand": "tsc",
  "connectTimeoutMs": 3000,
  "writeTimeoutMs": 15000
}
```

- `id`：代理侧自动生成（`default`、`printer2`、`printer3`…），**不允许手填**，必须与打印任务里的 `printerId` 一致。
- `host` / `port`：打印机地址，默认 `127.0.0.1:9100`（p9100 直通）。
- `cmdSet` / `brand`：由 ERP 侧维护（品牌、指令集），代理上报时不会被覆盖。
- `enabled`：代理侧开关，停用的打印机不会出现在打印选择列表。

### 2.3 任务表 `print_task`

`task_id`、`device_id`、`printer_id`、`status`、`total_bytes`、`sha256`、`error_code`、`message`、`created_at`、`updated_at`、`finished_at`。

状态流转：`pending → sent → accepted → success / failed / cancelled / timeout`。

### 2.4 代理 `config.json`

路径：`/etc/erp-print-agent/config.json`，权限 0600。

```json
{
  "deviceId": "agent-7F2K9Q",
  "token": "************",
  "storeName": "杭州西湖店",
  "printerModel": "TSC TE244",
  "server": {
    "url": "wss://www.innas.xyz:9999/ws/print-agent",
    "caFile": "/etc/erp-print-agent/ca.pem",
    "insecureSkipVerify": true,
    "serverName": "www.innas.xyz"
  },
  "printers": [
    { "id": "default", "name": "标签打印机", "host": "192.168.10.10", "port": 9100,
      "connectTimeoutMs": 3000, "writeTimeoutMs": 15000, "enabled": true }
  ],
  "limits": { "maxTaskBytes": 4194304, "queueSize": 8 },
  "reconnect": { "minMs": 1000, "maxMs": 30000 },
  "log": { "level": "info", "file": "", "maxSizeKB": 512 }
}
```

启动校验：`deviceId`、`token`、`server.url` 必填，且至少一台启用打印机；未配对时服务启动会失败，属于正常现象。

## 3. 配对流程

```
主机「打印管理 → 新增设备」            打印代理 LuCI「远程打印」
  │ 点「生成配对码」                      │
  │ POST /printAgent/pair/code           │
  │ ← 6 位配对码（10 分钟、一次性）        │
  │ 显示通信地址 + 倒计时                  │
  │                                      │ 填通信地址 + 配对码 + 门店/型号/打印机
  │                                      │ 点「配对」
  │                                      │ 1) 保存 config.json
  │                                      │ 2) erp-print-agent pair -code 123456
  │ ← POST /printAgent/device/pair ──────┤    （免登录，带 printers/version）
  │ 建台账：生成 deviceId + token         │
  │ → { deviceId, token, serverUrl, printers }
  │                                      │ 3) 写回 token/deviceId，重启服务
  │ ← WebSocket /ws/print-agent ─────────┤
  │ 页面每 3s 轮询 /printAgent/pair/status?code=xxx
  │ 状态变为「已接入」→ 自动关闭弹窗
```

规则：

- 配对码 6 位数字，**10 分钟有效、一次性**，存在后端进程内 Map 中；后端重启即失效。
- 重新生成配对码会替换当前展示的码；已使用的码再次提交返回 400。
- 配对接口只放行 `/printAgent/device/` 前缀，鉴权完全依赖配对码，不校验登录态。
- `serverUrl` 由主机按请求推导（优先 `X-Forwarded-Proto` / `X-Forwarded-Host`），固定路径 `/ws/print-agent`。
- 配对成功即 `paired=1`、`enabled=1`；设备编号与 Token 由主机分配，代理不再自己生成。

## 4. 连接与鉴权

代理连接 `ws(s)://<host>/ws/print-agent`，握手携带：

```
Authorization: Bearer <token>
X-Device-Id: agent-XXXXXX
X-Agent-Version: 1.0.0
```

握手校验（`PrintAgentHandshakeInterceptor`）：

| 情况 | 结果 |
| --- | --- |
| 缺少 X-Device-Id 或设备不存在 | 403 |
| `enabled = '0'` | 403 |
| Token 为空或不相等 | 401 |
| 通过 | 建立连接，注册到 Registry |

连接建立后主机主动下发 `auth.ok`：`sessionId`、`serverTime`、`heartbeatSec`（30s）、`maxTaskBytes`（4MB）。代理收到后补发离线缓存任务并上报一次 `agent.status`。

- `ping/pong`：应用层心跳，30 秒周期。
- `agent.status`：上报设备编号、版本、运行时长、打印机状态（在线/打印中/最近错误/最近任务时间）、队列深度；主机更新 `last_seen`、`version`、`client_ip`，并合并打印机列表。
- 同一 `deviceId` 新连接会替换旧连接。
- 断线时，该设备未完成任务统一置为 `failed`（`offline`）。
- 代理重连采用指数退避；鉴权失败（401/403）属于不可快速恢复错误，退避到 30 秒。

## 5. 打印机配置的合并规则（重点）

代理每次连接/状态上报都会带来自己 `config.json` 里的打印机列表。主机用「按 id 合并」：

| 字段 | 生效来源 |
| --- | --- |
| `name`、`host`、`port`、`enabled`、超时 | 代理上报（覆盖主机） |
| `cmdSet`、`brand` | 主机保存值（若存在则保留） |

结论：

- 在 ERP 里改打印机 IP/端口/名称，只会在下次上报前有效，之后被代理覆盖；**IP 与端口以代理设置页为准**。
- 品牌与指令集在 ERP 端设置才会长期生效（`PrinterDeviceConfig`）。
- 新增/删除打印机请在代理设置页操作；主机侧只做展示与指令集选择。
- 若代理删除了某台打印机，主机下次上报时同步消失。

## 6. 打印交互链路

1. 前端拉取设备列表，把每台设备的打印机扁平化为选项，key 为 `agent:<deviceId>:<printerId>`；选择结果记在 `localStorage`，设备/打印机不存在时自动回退到本机打印。
2. 点打印 → `POST /printAgent/print`：

```json
{ "deviceId": "agent-7F2K9Q", "printerId": "default", "copies": 1,
  "width": 320, "height": 240, "items": [...], "image": "data:image/png;base64,..." }
```

3. 后端解析指令集：取该设备 `printers` 中同 id 的 `cmdSet`，缺省 `TSPL`；由 `LabelPrinterService.buildLabel` 生成打印数据。
4. `PrintTaskDispatcher.dispatch`：
   - 校验设备在线、数据非空且不超过 4MB；
   - 生成 `taskId` 与 SHA-256，写入 `print_task`；
   - 发送 `print.task`（任务公告），随后按帧发送二进制数据（同一连接内串行）；
   - 代理回 `print.ack`（accepted / rejected），打印完成后回 `print.result`（success / failed / cancelled）；
   - 主机按 `timeoutMs`（默认 15s）+ 15s 兜底标记 `timeout`。
5. 代理侧：`printerId` 未配置直接拒绝；已配置则把整包数据写入该打印机的 `host:port`，队列串行、失败可重试并缓存补发。
6. 打印机离线或设备离线时，任务在第一步就会被拒绝，并带明确错误信息。

## 7. 主机页面交互（打印管理）

- **列表列**：门店/型号、设备编号、打印机（`N 台`）、状态、操作。
- **状态**：`待配对`（`paired != 1`，仅历史数据）/ `在线` / `离线`。在线判定以当前是否存在 WebSocket 连接为准，不看 `last_seen`。
- **新增设备**：弹窗第一步只展示通信地址（可复制）与「生成配对码」；第二步展示 6 位配对码、剩余秒数；第三步轮询到配对成功后展示设备编号与型号。
- **操作**：任务、删除。设备配置全部在代理端完成，主机不再提供编辑入口。
- **任务记录**：按设备查看最近 50 条，含状态、字节数、错误码与时间。

## 8. 代理 LuCI 设置页交互

菜单：`管理 → 服务 → 远程打印`。

| 区域 | 字段/按钮 | 行为 |
| --- | --- | --- |
| 顶部 | 状态徽标、门店·型号·版本 | 依据本地配置与进程状态显示 |
| 服务状态 | 运行中/已停止、自启、版本、启动/停止/重启/开机自启/取消自启 | 调用 init 脚本 |
| 连接主机 | 通信地址、配对码、配对/重新配对 | 保存配置 → 调 `pair` → 重启 |
| 门店与打印机 | 门店名称、打印机型号、打印机行（ID 只读、名称、地址、端口、启用）、添加/删除 | 保存到 config.json |
| 高级 | 证书主机名、跳过证书校验、日志级别、完整 JSON | 完整 JSON 非空时整份覆盖 |
| 底部 | 测试打印、保存并应用 | 测试为本地直连打印；保存后自动重启使配置生效 |

打印机 ID 生成规则：第一台固定 `default`，之后依次 `printer2`、`printer3`（跳过已占用编号），只读展示。

配对细节：点击配对时先把当前表单写入 config.json，再以 root 执行 `erp-print-agent pair -config /etc/erp-print-agent/config.json -code <6 位>`；成功后重启服务。配对请求的 TLS 默认跳过证书校验（主机多为自签证书），正式环境建议在主机配置可信证书。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 代理反复 401 | Token 与主机不一致：重新配对，或核对 `config.json` |
| 代理 403 | 设备不存在或 `enabled='0'`：主机侧确认设备状态 |
| 配对提示「不正确或已过期」 | 超过 10 分钟、已使用、或后端重启过：重新生成 |
| ERP 改 IP 不生效 | 打印机地址以代理上报为准，请到代理设置页修改 |
| 打印报「设备不在线」 | 代理未连上主机，检查通信地址、证书与网络 |
| 打印报「未配置该打印机」 | `printerId` 与代理侧不一致，核对两边 id |
| 标签内容乱码/不打印 | 指令集选错（TSPL/CPCL/DDPL/ESC-POS），在标签打印页调整 |
| 改打印机后列表没变 | 需等代理上报或重启代理服务 |

## 11. 安全与后续建议

- Token 明文存库、列表接口返回 Token；建议后续改为脱敏展示，仅在配对响应中下发。
- 配对会话存在进程内 Map，多实例部署会失效；如需扩容应改为数据库或 Redis。
- 配对码可被暴力尝试，建议增加按 IP 限流和失败次数锁定。
- `insecureSkipVerify` 仅建议调试使用，生产环境应配置可信证书与 `serverName`。
