# 部署数据与备份

## 目录约定

程序发布目录只放 JAR、前端静态文件和部署模板。持久化目录与程序版本分开：

- Windows 本地部署：`deploy.config.json` 中的 `dataDir` 和 `backupDir`，默认位于 `D:/jshERP/`。
- Linux Compose 部署：`deploy/.env` 中的 `JSHERP_DATA_ROOT` 和 `JSHERP_BACKUP_ROOT`，默认位于 `/srv/jsherp-data` 和 `/srv/jsherp-backup`。
- 应用数据包含上传文件、OCR/证书配置和日志；MySQL 数据目录和备份目录分开保存。

首次运行新版 Windows 部署脚本时，如果新版数据目录为空而仓库旧 `data/` 目录有内容，脚本会复制旧内容并保留原目录，不会覆盖已有的新目录。

升级或替换程序时不要删除这些目录。迁移服务器时，先停止应用和数据库，再复制 MySQL 数据目录及应用文件；或者使用 SQL 备份恢复数据库，并单独复制上传文件和配置。

## 数据库配置

应用通过 `SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME` 和 `SPRING_DATASOURCE_PASSWORD` 读取数据库连接。生产环境使用专用的 `jsherp` 账号，不要使用 root 账号。Redis 连接可通过 `SPRING_REDIS_HOST`、`SPRING_REDIS_PORT` 和 `SPRING_REDIS_PASSWORD` 设置。

首次部署 Compose：

1. 将 `deploy/.env.example` 复制为部署目录中的 `.env`。
2. 设置唯一且足够长的 `MYSQL_ROOT_PASSWORD` 和 `APP_DB_PASSWORD`，并确认 `JSHERP_DATA_ROOT`、`JSHERP_BACKUP_ROOT` 指向持久化磁盘。
3. 创建目录并确保 Docker 服务账号有权读写。
4. 准备数据库表结构和初始数据后启动 Compose。MySQL 不映射主机端口，只允许应用在内部网络访问。

`deploy.ps1` 只会上传 `.env.example`，不会传送服务器 `.env`；它会在部署前检查远端 `.env` 是否已配置。SSH 密码由本地 `JSH_SSH_PASSWORD` 环境变量或未入库的 `tools/ssh/password` 提供，并校验脚本中固定的 HostKey。


已有 MySQL 数据卷升级时，MySQL 不会因为 Compose 环境变量变化而自动创建新用户。管理员需先在原数据库中创建应用账号并授予 `jsh_erp` 所需权限，再切换应用配置：

```sql
CREATE USER 'jsherp'@'%' IDENTIFIED BY '替换为 APP_DB_PASSWORD 的值';
GRANT ALL PRIVILEGES ON jsh_erp.* TO 'jsherp'@'%';
FLUSH PRIVILEGES;
```

数据库端口保持内网可达即可。其他 Web、移动端或客户端通过 ERP 后端 API 访问业务数据，不直接连接 MySQL。

## 备份建议

- 定期将 `mysqldump` 生成的 SQL 文件写入 `backupDir/mysql`（Linux 默认 `/srv/jsherp-backup/mysql`）。运行账号凭据通过受限权限的 MySQL 客户端配置文件提供，不要放在命令行参数、代码仓库或普通日志中。
- 将 `dataDir/upload` 或 Compose 的 `/srv/jsherp-data/app/upload` 纳入文件备份；临时导出文件可按保留策略清理。
- 备份目录应同步到另一块磁盘或另一台机器，并设置保留周期。
- 定期在隔离环境恢复数据库和上传文件，确认备份可用。

`deploy-local.ps1` 只创建应用数据目录和备份目录，不会自动执行数据库备份。定时任务需由服务器管理员按实际 MySQL 地址、凭据和保留周期单独配置。

## 192.168.100.1 一键发布

在仓库根目录执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy.ps1 -Frontend
```

该命令会构建后端和前端、校验服务器上的 `.env` 与外置数据卷、生成 SQL 部署前备份、上传发布文件，然后仅重建应用和 Nginx。MySQL 与 Redis 不会随应用发布重启。部署后检查后端 HTTP `9998` 和对外 HTTPS `9999`；若检查失败，脚本返回非零状态。

目标默认是 `root@192.168.100.1:/root/jsherp`。服务器必须先配置 `/root/jsherp/.env`（参考 `deploy/.env.example`），并确保 `JSHERP_DATA_ROOT=/srv/jsherp-data`、`JSHERP_BACKUP_ROOT=/srv/jsherp-backup`。本机 SSH 密码从 `JSH_SSH_PASSWORD` 环境变量或被 Git 忽略的 `tools/ssh/password` 读取。凭据、`.env` 和服务器证书不要提交。

每次部署前的 SQL 文件写入 `/srv/jsherp-backup/mysql/jsh_erp-predeploy-<时间戳>.sql`。2026-11-09 本次部署生成了 `jsh_erp-predeploy-20261109-173849.sql`。此备份不替代周期性异机备份；保留策略和恢复验证仍需运维维护。脚本预检外置挂载，若数据库或备份目录仍是 Docker 命名卷则停止，以免误切到空目录。

本次发布实测外部 HTTPS 返回 200，后端 HTTP 检查通过，外部 MySQL 3306 端口不可达；MySQL/Redis 容器未重启。
