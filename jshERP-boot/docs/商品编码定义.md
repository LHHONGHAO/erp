# 商品编码定义

本文统一商品相关编码的含义。现有系统中的“商品码”和“SKU码”用于识别商品及规格组合；逐件追踪库存需要新增单件码。

## 1. 商品码（SPU码）

- 含义：识别一个商品款式/基础商品，不区分颜色、尺码等规格，也不代表某一件实物。
- 当前字段：`jsh_material.code`。
- 新生成规则：`SP` + 2位类型码 + 款号（例如 `SP02-CNG2T2005`）。款号优先取商品型号字段；未填写时系统生成短码。
- 使用场景：商品资料识别、关联其下属 SKU 规格。
- 规则：生成后应保持稳定，不因名称、分类或规格调整而复用或改写。

## 2. SKU码（规格码）

- 含义：识别一个商品款式下的一个规格组合，例如颜色、尺码组合；同一 SKU 可以对应多件库存。
- 当前字段：`jsh_material_extend.sku_code`，并通过 `material_extend_id` 关联商品规格记录。
- 新生成规则：SPU码 + 每个规格属性的属性值编码，按品类规格顺序拼接（例如 `SP02-CNG2T2005-01-04-08`）。新生成的属性值编码为纯数字序号，不再加颜色、尺码等前缀；完整规格仍以规格记录及 `spec_values` 为准。
- 使用场景：按规格查询商品、汇总库存、采购和销售明细。
- 规则：一个规格组合应对应一个稳定 SKU 码；修改展示名称不应改变已有 SKU 码。

## 3. 单件码（商品标签码，待建设）

- 含义：识别一件具体实物。每件独立商品一个码；多个单件码可以关联同一个 SKU。
- 当前状态：现有数据模型尚未实现，SKU码不能代替单件码。
- 建议字段/实体：独立的单件库存记录，至少包含单件码、SKU记录ID、仓库/库位、状态及入库来源单据；单件码应有数据库唯一约束。
- 使用场景：收货贴标、逐件扫码入库、销售出库、退货、换货、盘点和报损追溯。
- 新生成规则：SKU码 + 单件唯一流水号（例如 `SP02-CNG2T2005-R20-170-00000001`）。生成函数已提供唯一流水号参数；流水号必须由持久化、原子递增的序列源分配。
- 建议规则：收货确认时按实际到货数量生成；打印标签并扫码确认入库后才进入可用库存。销售时关联销售明细并将状态更新为已售，不物理删除编码或历史流转记录。

## 4. 关系与术语

```text
商品码（SPU） 1 ── 多 SKU码（规格组合） 1 ── 多 单件码（实物）
```

界面和文档中的“商品码”专指 `jsh_material.code`；“SKU码”专指 `jsh_material_extend.sku_code`；“单件码/商品标签码”专指未来逐件库存追踪编码。不得将单件码称为 SKU 码，也不得以 SKU 码直接表示单件库存。

## 5. 当前实现边界

当前库存记录以商品/SKU维度汇总数量。建立单件码后，汇总库存仍可保留作查询和报表，但应由单件库存流转与出入库单据共同维护，并通过核对保证汇总数量一致。
